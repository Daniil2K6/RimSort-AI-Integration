# Доработки чата и проверка MCP-интеграции

## Что изменено

- В сообщениях чата постоянно доступна кнопка «Копировать», с подтверждением «Скопировано». Контекстное меню копирует выделенный фрагмент или всё сообщение; для ответов доступно копирование исходного Markdown. Кнопка находится под текстом и не закрывает его.
- Общий механизм `app/utils/text_copy.py` делает информационные надписи выделяемыми, поддерживает Ctrl+C/Cmd+C и контекстное меню. Копируется текст без HTML. Ссылки сохраняют своё поведение; перетаскивание модов и собственные меню приложения не заменяются.
- Таблицы BaseModsPanel, включая ACF Log Reader, допускают выделение ячеек. Выделенные данные копируются в TSV по порядку видимых колонок; вместо кнопки Workshop копируется URL. Флажки выбора модов для операций работают отдельно от текстового выделения.
- В Player Log доступны «Копировать строку» и «Копировать весь отображаемый текст». Второй пункт копирует текущий текст редактора, включая применённый фильтр, а не весь файл с диска. Удалено повторное подключение контекстного меню.
- Выделение текста пути к моду перетаскиванием не открывает папку; обычный одиночный щелчок сохраняет прежнее поведение.
- Ошибки подключения и получения списка моделей используют единые русские объяснения и инструкции. Отдельно распознаются неверный ключ, недоступная модель, недостаток средств/квоты, частота запросов, явные региональные ограничения, отсутствие tools, контекст, TLS, timeout и сбой сервиса.
- Неопределённая ошибка доступа остаётся неопределённой: HTTP 403 сам по себе не объявляется блокировкой страны. Неизвестные ответы не превращаются в выдуманную конкретную причину. Точный исходный текст провайдера может оставаться английским в диагностике, пояснение и шаги решения — русские.
- Диагностика включает код, HTTP-статус, сервер, модель и Retry-After при наличии. Из неё удаляются известный API-ключ, Bearer-значения, типовые секреты и учётные данные URL. Полные HTML-страницы ошибки не выводятся. Не следует считать маскирование универсальным распознавателем любых персональных данных из ответа стороннего сервера.
- Ошибка внутри SSE после HTTP 200 больше не выглядит как пустой успешный ответ. Оборванный поток не возвращает готовые вызовы инструментов. Некорректные аргументы модели не исполняются.
- `apply_modlist_plan` и `apply_modlist_batch` теперь требуют подтверждения встроенного агента. Запись ModsConfig.xml идёт через временный файл рядом с целью и замену; ошибка сериализации сохраняет предыдущий файл. Это атомарная замена файла, а не транзакция между всеми процессами.
- Запуск IPC больше не сообщает успех, если QLocalServer.listen вернул false; причина ошибки фиксируется в журнале.
- Панель чата сохраняет реальные tool calls/results рабочего потока и передаёт их в следующий запрос. Контекст обрезается целыми пользовательскими ходами, чтобы не оставлять ответ инструмента без вызова. Оценка размера учитывает аргументы tools, а не только фиксированную надбавку.
- Промежуточный текст агентного раунда отделён от итогового ответа. Системный промт опирается на текущие schemas, не навязывает универсальный порядок модов, не требует любой ценой добиться ok=true и не предписывает всегда сохранять модпак.

## Где интеграция пока неполная

Это результаты чтения существующего кода, а не реализованные здесь новые возможности.

1. **Внешний MCP связан с GUI.** `rimsort mcp` при старте подключается к работающему окну через ограниченный локальный JSON-протокол с подтверждением. `--headless` явно выбирает работу с диском. Отключение GUI после подключения возвращает ошибку; автоматического повтора изменений нет.
2. **Рабочий список синхронизирован.** В режиме подключения список читается из MainContent, а сохранение сравнивает снимок с текущим GUI и выбранным конфигом. Проверка, атомарная запись и обновление видимых списков выполняются в одном обработчике главного потока. Неустановленные моды могут остаться в файле при allow_missing, но не представлены установленными элементами GUI. Для смены режима подключения перезапустите MCP.
3. **expected_revision пока необязателен.** Проверка revision перед записью ещё не является блокировкой конкурирующей записи другим процессом. Новый промт требует актуальную revision, но для строгой гарантии нужно серверное обязательное условие и сериализация check+apply.
4. **Бюджет контекста приблизительный.** Он защищает целостность пользовательского хода, но необходимый последний ход может превышать бюджет. Schemas и рост результатов внутри run_agent ещё требуют отдельного общего бюджета. Не стоит выдавать оценку за точный provider usage.
5. **Получение моделей пока синхронное.** Запрос /models в AIProviderDialog может блокировать окно до timeout. Следующее улучшение качества — перенос запроса в отменяемый worker с безопасным закрытием диалога; новые пользовательские функции для этого не нужны.
6. **Опциональные параметры провайдера.** AIClient по-прежнему передаёт stream_options.include_usage каждому потоковому endpoint. Для полной совместимости нужен capability-параметр: некоторые совместимые серверы поддерживают tools и SSE, но не этот дополнительный параметр. Ошибка не должна автоматически перезапускать уже выполненные операции.
7. **Закрытие во время долгой операции.** ChatPanel.shutdown после пяти секунд по-прежнему вызывает worker.wait без ограничения. Сетевая генерация отменяется, но длительный доменный инструмент может задержать закрытие. Нужен согласованный жизненный цикл отмены/ожидания инструментов; уничтожать работающий QThread нельзя.

Приоритет следующего прохода: общий execution budget и provider capabilities → отмена долгих операций. Новые инструменты сами по себе эти разрывы не исправляют.

## Ручная проверка

1. В русском интерфейсе откройте чат: «Копировать» видно без наведения. Скопируйте выделенную фразу, сообщение целиком и исходный Markdown через меню.
2. Выделите число активных модов и скопируйте Ctrl+C/Cmd+C. Проверьте сведения о моде и путь; выделение пути не должно открывать папку.
3. В ACF Log Reader выделите несколько ячеек и вставьте в текстовый редактор/таблицу. Проверьте источник URL Workshop; флажки операций не должны менять своё значение от копирования.
4. В Player Log проверьте копирование выделения, строки и отображаемого текста после фильтра.
5. На тестовом endpoint воспроизведите model_not_found, insufficient_quota, обычный HTTP 429, явный unsupported_country и неопределённый HTTP 403. Объяснения должны отличаться, а ключ — отсутствовать в копируемой диагностике.
6. Проверьте два раунда агента и повторный вопрос: пояснение не склеивается с итогом, история сохраняет пары вызов/результат.

Диагностика сверялась с [документацией ошибок OpenRouter](https://github.com/OpenRouterTeam/docs/blob/main/api_reference/errors-and-debugging.mdx) и [классами ошибок aiohttp](https://docs.aiohttp.org/en/stable/client_reference.html). Это подсказки по сигналам провайдера, а не гарантия одинаковых сообщений всех OpenAI-compatible серверов.
